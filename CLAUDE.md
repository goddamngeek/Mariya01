# Алексей — телеграм-бот поверх Trilium

Личный бот на двоих: **МАША** (`335712401`) и **ОСТАП** (`136382691`), см.
`app/people.py`. Хранилища — Trilium через ETAPI (`app/trilium_client.py`) и
Firefly III через его REST API (`app/firefly_client.py`).

**Языковой модели в боте нет ни одной.** Всё делается кодом.

Этот файл — про решения и грабли, а не про устройство кода. Код читается
сам; ниже то, что из него не следует.

## Как деплоить

`git push origin main` — дальше деплой сам. Ждать так:

```bash
source .env && until curl -s "$BOT_URL/health" | grep -q '"ok":true'; do sleep 5; done
```

**Как понять, что отвечает новая сборка.** `/health` отдаёт `started_at` —
время старта процесса; оно меняется на каждом деплое. Дождался, чтобы оно
стало новее момента пуша, — значит перед тобой новая версия. Без этого
маркера отладка вырождается в гадание: можно долго щупать старый контейнер
и искать баг в уже исправленном коде (так и было). Если в переменные
Northflank добавить `BUILD_REV` с хешем коммита, `/health` покажет и его.

**Что упало — смотреть в `/sync/errors`**, а не деплоить ради трейсбека.
Там последние 50 ошибок: фоновые задачи, потоки диалогов и необработанные
исключения роутов. В памяти, поэтому перезапуск их теряет.

`.env` (`DATABASE_URL`, `TELEGRAM_BOT_TOKEN`, `SYNC_BEARER_TOKEN`,
`BOT_URL`) в гит не идёт. Однажды `git add -A` утащил `cookies.txt` с
живыми сессионными токенами в запушенный коммит — **никогда не коммитить
скопом**, только перечисляя файлы.

Проверка перед пушем: `pyflakes` по изменённым файлам плюс
`python -c "import app.main"` — импорт ловит и битые импорты в `sync.py`,
и опечатки в декораторах.

## Главный принцип

Логика уехала **с агентного цикла Odysseus на детерминированный код бота**,
и уехала до конца: 30 августа 2026 Odysseus убран целиком. Всё, что можно
решить `if`-ом, регуляркой или кнопкой, решается ими — так оно не ломается
молча.

Где текст неоднозначен, бот **спрашивает кнопкой**, а не угадывает моделью.
Кнопки детерминированы и проверяемы; лишнее нажатие дешевле неверной суммы,
замеченной через месяц.

Что ушло вместе с Odysseus: свободный разговор (им не пользовались — один
вызов за неделю перед удалением), записи в журнал, китайские слова,
продажи, запасной разбор времени напоминаний. Контейнеры на VPS остановлены,
но не удалены: захочется поиск по журналу — поднимутся обратно.

## Исчезание сообщений

Единый механизм — `app/threads.py`. У ветки **одно** терминальное
состояние и три входа в него: успех, таймаут, реакция.

**Реакция — это не удаление.** Это досрочное завершение ветки, которое
уже влечёт обычный разбор. Разница важна: разбор один и тот же во всех
трёх случаях.

**Ежедневник — сознательное исключение.** Он не открывает ветку вообще:
его сообщения живут до явного `/clear`, и ответ можно отредактировать
задним числом (`handle_message_edit` в `app/service.py`). Правка задним
числом работает **только** для ежедневника — не для трекеров активности
и не для цитат.

Ночной очистки нет, её убрали. Чат чистится только по `/clear`.

## Расписание (`app/scheduler.py`, всё по Москве)

| Когда | Что |
|---|---|
| пн–пт 12:30 / 18:00 / 21:30 | чек-ины ежедневника |
| сб–вс 23:00 | один вечерний чек-ин (на выходных не успеваем отвечать) |
| 9:00 / 14:00 / 20:00 ежедневно | «Круг чтения», три порции одного дня |
| вс 12:00 | напоминание позвонить бабушкам |
| сб 10:00 | обзор рынка |
| 00:05 | слоты напоминаний про воду на день |

Каждый слот чек-ина закрывает предыдущий — иначе неотвеченный вопрос
блокировал все следующие. Обратная сторона: ответ реплаем возвращает в
любой чек-ин, даже вчерашний.

## Канал @blessandbeblessed

**В канал идёт ТОЛЬКО «Круг чтения» и больше ничего.** Источник —
`app/krug_chteniya.json` (366 дней, 2701 мысль), сборка — `app/parables.py`,
разбиение детерминировано датой.

День уходит **тремя порциями** (9:00 / 14:00 / 20:00), продолжающими друг
друга, а не одной. Одна выжимка в 900 символов показывала около 30% дня —
остальное не видел никто никогда.

**Порог длины мысли равен размеру порции** (900). Мысль, которая не влезает
в одно сообщение, не показывается вовсе: резать её по живому нельзя, а
пропустить — можно. Порог был 500 и выбрасывал 18% мыслей, державших 48%
текста книги; на трёх отправках это значило, что вечерней нечего сказать
четыре дня из пяти.

Короткий день кончается раньше вечернего слота — тогда в 20:00 не уходит
ничего, и это нормально: вторая порция есть у 95% дней, третья у 61%.

## Грабли Trilium

- **Шаблон не переносит тело через ETAPI.** Отношение `~template` даёт
  наследование атрибутов, но не содержимое. Тело `_ШАБЛОН_КНИГА` надо
  забирать и копировать явно.
- **Очищенная в интерфейсе дата остаётся пустой строкой**, а не исчезает.
  Проверять на истинность значения, а не на наличие метки — иначе
  дочитанной считается книга с `readingEnd=""`.
- **Цитаты лежат после последних разделов и своего `<h2>` не имеют.**
  Перезапись раздела обязана кончаться на первом `<hr>`, иначе заполнение
  «Похожих книг» стирает из заметки все цитаты (уже случалось).

## Грабли Postgres

**`CREATE TABLE IF NOT EXISTS` не добавляет колонки существующей
таблице.** Каждое изменение схемы — отдельный `ALTER TABLE`. Симптом
пропущенной миграции: эндпоинт молча отдаёт 500 на живом проде, хотя
локально всё импортируется.

## Грабли Telegram

- `message_reaction` **не входит** в `allowed_updates` по умолчанию, см.
  `ensure_webhook_allowed_updates`.
- `deleteMessage` отказывается трогать сообщения старше 48 часов.
- Вебхук передоставляет апдейт, если не ответить примерно за минуту —
  поэтому всё, что лезет в Trilium, уходит в `app/background.py:spawn`.

## Разбор ответа «расскажи подробнее»

`split_book_details` в `app/service.py`: сначала пробуются заголовки
своей строкой (нужно минимум два), и только потом — абзацы по позиции.
Порядок именно такой, потому что шаблон сам перечисляет четыре заголовка
четырьмя подряд идущими строками и провоцирует ответ без пустых строк —
для разбиения по абзацам это один кусок, и весь ответ уезжал в «Об
Авторе».

## Диагностика

`/sync/*` за bearer-токеном (`app/sync.py`) — смотреть **живое состояние
прода**, а не догадываться. Особенно `/sync/note?title=…` (что реально
записалось в заметку), `/sync/open_prompt` (на какой вопрос ответит
следующее сообщение), `/sync/active_books`.

Одноразовые чинящие эндпоинты — добавить, применить, **сразу удалить**.
